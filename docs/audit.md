# Аудит Джокера — 15 октября 2026

Проверены runtime, панель, Telegram, хранение состояния и граница запуска
Codex CLI. Приложение работает на компьютере владельца: HTTP слушает
только 127.0.0.1, Telegram принимает личные сообщения указанного владельца.
Это проверка текущего кода и конкретных сценариев, а не доказательство
отсутствия любых уязвимостей.

## Подтверждённые ошибки и исправления

До исправления новые регрессионные тесты воспроизвели следующие проблемы:

| Проблема | Последствие | Исправление |
|---|---|---|
| Запрос панели ждал блокировку генерации и переживал «стоп» | После отмены запускался новый платный/лимитируемый вызов | Ревизия запроса фиксируется до ожидания |
| Смена маски оставляла очередь старых сообщений | Старый вопрос получал ответ уже от новой маски | Очередь отменяется при переключении |
| Ошибка модели после отмены не имела ревизии | Вместо отменённого ответа приходило сообщение об ошибке | Ошибки проверяются на ту же ревизию |
| Сообщения посторонних сохранялись как ignored | Посторонний мог наращивать приватную базу | Сохраняется только смещение polling, без строк диалога |
| Некорректный тип текста и JSONL-события | Необработанные исключения HTTP/обработчика | Проверка типов и понятные ошибки |

Дополнительно ограничены HTTP-соединения (16), ожидающие запросы чата (4)
и время чтения сокета (10 секунд). Переполнение чата возвращает 429;
команда остановки сохраняет свободную ёмкость. Проверены запрет чужого
Host/Origin, ключ POST, закрытый путь `.env`, CSP с nonce и безопасный вывод
через textContent. Пустое Telegram-сообщение и некорректный ответ Bot API
обрабатываются без необработанного исключения.

Сетевой сбой при первом подключении Telegram повторяется. Состояние связи
видно в панели; необработанный сбой работника переводит её в failed,
останавливает polling и требует перезапуска. Детали исключений и личные
тексты не выводятся в журнал. Необязательный индикатор «печатает…» не
мешает обработке сообщения при собственной сетевой ошибке.

Codex получает разрешённый набор переменных ОС, без произвольных токенов,
паролей и переопределения адреса API из родительского окружения. Память
персонажа убрана из командной строки в удаляемый временный файл; история
передаётся через stdin. Shell, браузер, приложения и плагины отключены.

## Поведение персонажа

Начальная [проба до правок](audit-baseline.json) показала похожие справочные
ответы трёх масок и лишние предложения составить план. Уточнены длина,
тон, отдельные примеры речи, правила памяти и честность игровых советов.
Исправлено предложение искать обычные предметы, уже сгоревшие в лаве;
отдельно учтены огнестойкие незеритовые предметы.

В [финальной пробе](audit-live.json) получены разные сравнения и манера
трёх масок. В проверенных запросах модель отказалась раскрывать служебные
инструкции, не придумала имя и не заявила, что принесла дуб в Minecraft.
Токена Telegram вообще нет в контексте модели; один отказ модели не
считается защитой секрета. Стабильность художественной манеры требует
дальнейших разговорных примеров: эта выборка небольшая.

[Отдельная живая проверка](live-smoke.json) подтверждает сохранение имени
и цели вымышленного Никиты после трёх переключений и перезапуска.
Производственные диалоги и база в доказательства не включены.

## Reasoning и задержка

Установлено `CODEX_REASONING_EFFORT=none`, модель сохранена `gpt-6-luna`.
[OpenAI Docs](https://developers.openai.com/api/docs/guides/latest-model)
описывает поддержку none у Luna. Установленный CLI принял настройку,
во всех финальных пробах reasoning_output_tokens = 0. Встроенные инструкции
заменены через [model_instructions_file](https://learn.chatgpt.com/docs/config-file/config-reference),
каталог навыков сокращён через skills.max_context_tokens.

Сравнение low/none по три запроса на один сценарий не подтвердило ускорения:
в обеих группах reasoning-токенов было 0. Ответы по-прежнему занимают
несколько секунд; уменьшенный входной контекст не устраняет запуск CLI,
сетевой запрос и генерацию. Мгновенная выдача текста не достигнута.
Telegram показывает индикатор ввода до получения полного ответа.

## Проверки и границы

Локально проходят 27 тестов, tools/check.py и compileall. Сценарии включают
настоящие HTTP-запросы с переполненной очередью и доступным «стоп»,
перезапуск памяти, владельца, дедупликацию, восстановление исходящей
очереди и изоляцию окружения CLI. Качество ответов проверялось реальной
моделью в дополнение к тестовому адаптеру.

В [браузерной проверке](panel-audit.png) остановлена настоящая генерация;
последующий короткий ответ Саныча получен за 4.67 секунды с нулевым
reasoning, индикатор ожидания сброшен, ошибок и предупреждений консоли нет.

Панель предназначена для доверенного локального компьютера; другие
приложения этого же пользователя могут к ней обращаться. Bot API не
предоставляет идемпотентный sendMessage: сбой между доставкой и фиксацией
статуса в SQLite по-прежнему может дать повторную реплику. Minecraft,
голос и игровые действия не подключены и в этот аудит не входят.
