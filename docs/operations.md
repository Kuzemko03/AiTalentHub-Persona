# Цель, сон и постоянный запуск

Эти части реализованы для последующей совместной проверки. Автозапуск в системе
владельца не устанавливался, игровые и аудиоустройства не включались.

## Самостоятельная работа

1. `/цель Добудь 16 дубовых брёвен и принеси мне` — сохранить цель и остановить
   старую задачу. Можно сделать это в новой карточке панели.
2. `/автономность вкл` — явно разрешить самостоятельные игровые решения.
3. `/план` — цель, последние решения и результаты инструментов.
4. `/автономность выкл` или «Стоп» — отменить решение модели, остановить
   игру и оставить цель/план в памяти.

Раз в `RUNTIME_INTERVAL` секунд (по умолчанию 60, минимум 15) цикл проверяет
события. При закрытой игре, занятом текстовом контуре или выполняющемся
поручении модель не вызывается. Для решения она получает текущую маску,
поставленную цель, состояние игры и до восьми последних шагов.
Личные диалоги Telegram в этот контекст не входят.

Модель возвращает структурированное решение: ждать, следовать, добыть,
добыть и передать либо поспать. Аргументы проверяются: только дуб,
булыжник и земля, количество 1–256. Исполнение идёт через тот же адаптер.
Цикл не рассылает сообщения, не публикует посты и не выполняет код модели.
Это ограниченная автономность вокруг игровых поручений, не свободное
управление всем компьютером или самостоятельное строительство любого объекта.

`RUNTIME_DAILY_REQUESTS=20` ограничивает решения за сутки UTC. Они дополнительно
считаются в общем `MAX_DAILY_REQUESTS`. Входящий разговор прерывает ещё не
исполненное фоновое решение. Журнал хранит 20 последних шагов в локальной базе.

Перед игровым действием сохраняется намерение. Если процесс оборвался,
следующий запуск восстанавливает цель, но ставит автономность на паузу:
сначала проверьте мир и оставшуюся задачу. Неоднозначный результат и передача
предметов на землю также приостанавливают цикл. Он не повторяет передачу,
пытаясь получить более удобный ответ API. После ручной проверки можно задать
новую цель. Факт подбора предметов владельцем автоматически не устанавливается.

## Сон и пробуждение

- `/сон` — до явного пробуждения.
- `/сон 30` — на 30 минут (1–1440).
- `/проснись` — вернуться к разговору. После ручного сна автономность
  включается отдельно, если она нужна.
- `QUIET_HOURS=23:00-08:00`, `UTC_OFFSET=3` — автоматический сон по местному
  времени с фиксированным смещением. Пустое значение выключает расписание.

Сон останавливает текущую игровую задачу, текст и звук, сохраняет цель.
Спящий персонаж не вызывает модель для обычных реплик и комментариев,
не создаёт фоновые посты. Команда пробуждения остаётся доступна в панели,
Telegram и текстовом игровом чате владельца. Голос во сне не распознаётся.
Расписание имеет приоритет: ручное пробуждение внутри тихих часов приведёт
к повторному сну на следующем тике. При окончании планового сна сохраняется
предыдущее разрешение автономности, если владелец не нажал «Стоп».

При потере Py4J остановка может остаться неподтверждённой: проверьте сам
Minecraft. Сон программы не закрывает игровой клиент и не делает его бессмертным.

## Сервер

В `.env` можно задать `MINECRAFT_SERVER=адрес:порт` и `MINECRAFT_AUTOCONNECT=1`.
Тогда включённый адаптер попросит уже запущенный клиент UnionClef войти на
сервер, если мир ещё не открыт. Проверяется ник клиента до подключения;
повтор — не чаще раза в минуту. Во сне новые подключения не запрашиваются.
Без этого разрешения адаптер только ждёт открытый мир.

Лаунчер, игровой профиль, Java и моды устанавливаются отдельно. Пароли сервера
не отправляются из этой программы. Не выставляйте Py4J-порты в интернет.
Работа на публичном сервере требует соблюдения правил этого сервера и проверки
того, как UnionClef разбирает его чат. Публичный GitHub не означает публикацию
панели управления: она по-прежнему доступна только на 127.0.0.1.

## Постоянный запуск в Windows

Обычный запуск остаётся прежним. Для перезапуска после сбоя есть supervisor:

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/supervise.py --telegram --minecraft --voice
```

Флаги можно убрать. После ошибки — до пяти попыток с растущей паузой;
после пяти минут устойчивой работы счётчик ошибок сбрасывается.
Чистый выход завершает supervisor. Логи ограничены четырьмя файлами до 2 МБ
в `data/logs`. Второй долгоживущий экземпляр из той же папки отклоняется
файловой блокировкой, чтобы не было двух Telegram poller и двух игровых очередей.

Когда обычный запуск проверен, автозапуск можно явно установить:

```powershell
.\Autostart-Joker.ps1 -Action Status
.\Autostart-Joker.ps1 -Action Install -Minecraft -Voice
.\Autostart-Joker.ps1 -Action Remove
```

Без Telegram добавьте `-WithoutTelegram`. Установка регистрирует задачу текущего
пользователя для следующего входа в Windows, не запускает её немедленно.
Используется `pythonw.exe`, без консольного окна; логи доступны в `data/logs`.
Смена расположения проекта требует переустановки задачи. Скрипт проверен
синтаксически; реальный вход/выход Windows и работа устройств после входа
ещё не проверялись. Python-приложение не запускает Minecraft-лаунчер за пользователя.

## Резервные копии

При работе длинного процесса раз в сутки UTC создаётся согласованная SQLite-копия
в `data/backups`, затем выполняется `PRAGMA integrity_check`. Сохраняются
последние 14. Ручная копия:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m joker backup
```

Копия содержит личную память, диалоги, настройки и план. Она не содержит `.env`,
фотографии ролей или установку игры. Это локальная копия на том же диске,
не защита от потери самого диска. Для переноса нужны также `.env` и `data/roles`.

Автоматическая проверка восстановления открывает отдельную копию и читает
память/цель. Восстановление настоящей базы вручную выполняйте только при
остановленном Джокере, сохранив текущую папку `data` целиком; нельзя подменять
базу под работающим процессом или смешивать старую базу с чужими WAL/SHM.
