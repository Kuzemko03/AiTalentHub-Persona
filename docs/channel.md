# Telegram-канал «Джокер»

Канал: https://t.me/JokerAiTalent. Первый выпуск с картинкой опубликован
15 октября 2026: [иллюстрация](https://t.me/JokerAiTalent/2),
[история](https://t.me/JokerAiTalent/3). Доставка подтверждена Bot API,
журналом очереди и публичной страницей Telegram. Скриншот — `channel-live.png`.
Название канала остаётся «Джокер».

## Содержание

Посты — небольшие истории от лица выбранного человека с ситуацией,
развитием и финалом. С 16 октября 2026 роли — отдельные человеческие
образы с собственной внешностью; обязательные споры внутренних масок
убраны. Сантехник рассказывает свою историю, домохозяйка — свою.
Описание новой реализации и реальные пробы — в `roles.md`.

Редакционные правила находятся в `channel/EDITORIAL.md`, десять разных
отправных идей — в `channel/ideas.json`. Подготовлены две стартовые истории
и два изображения в прежнем стиле. Оставшиеся черновики этого стиля
перенесены в локальный архив. Новые образы людей — в `channel/assets/roles`.
Скриншоты NetTyan послужили примером формата дневника; чужие истории,
переписки и изображения не копировались.

Текстовый генератор получает основу персонажа, публичную очередь и явно
переданные `/событие` сведения. Он не получает личные диалоги, память
игрока и Telegram-токен. Без публичного события создаётся вымышленная
сцена с соответствующей подписью. Реальные игровые достижения нельзя
выдумывать. Контроль качества текста и картинки выполняет агент расписания;
автоматическая проверка структуры сама по себе не подтверждает интересность или правдивость.

## Ручной режим и картинки

По просьбе владельца автоматизация «Джокер: вести канал» поставлена на паузу,
а `channel_enabled` выключен. Посты не готовятся и не публикуются сами.
Текущая задача — настроить качество письма. В панели можно задать тему и
подготовить черновик; в Telegram — `/пост новый тема`. Публикация требует
отдельной ручной команды владельца. Очередь и картинки сохраняются.

В `channel/EDITORIAL.md` закреплены конкретный крючок в первых строках,
развитие вместо повторения одной шутки, разговорный русский, разные
желания масок и редактура слабой фразы перед выдачей. Объём следует
материалу: короткая сцена не растягивается до длинного поста. Эти правила
задают направление; качество будущих текстов предстоит проверять на примерах.

Сохранённый механизм расписания не запускается сам по себе. Если владелец
позже отдельно разрешит его вернуть, порядок работы будет: `channel next`
→ проверка черновика → подготовка иллюстрации → `channel attach`
→ `channel publish` → проверка подтверждения.
Очередь хранит отдельные слоты на дату и время. Повторный запуск использует
тот же черновик, а опубликованный пост повторно не отправляется.
Окно каждого слота ограничено; новая дата не вызывает выпуск за прошлую.

Генерация новых изображений выполняется встроенным image_gen в Codex,
вне ограниченного текстового процесса бота. Отдельный API-ключ для этой
схемы не требуется, расходуются доступные лимиты Codex. Постоянный
референс выбирается по роли автора. Фото Михалыча и Валентины Петровны —
`channel/assets/roles`, точные промпты — `channel/assets/roles/prompts.txt`;
режим — встроенный инструмент, не API CLI.
Новые картинки хранятся в игнорируемом `data/channel/media`. Сейчас
генерация картинок также выполняется только по отдельному запросу.

Если фото и весь текст с подписями укладываются в лимит 1024 единицы UTF-16,
они отправляются одним сообщением с одной веткой комментариев. Длинная
история отправляется отдельно, ответом на фотографию.
При будущем включении автоматизации нельзя выпускать пост без подходящей картинки.
Явная кнопка «Опубликовать текст» в локальной панели допускает ручной
текстовый пост по выбору владельца.

## Управление

Команды доступны только владельцу бота в личном чате:

| Команда | Действие |
|---|---|
| `/канал` | Состояние и расписание |
| `/канал @имя` | Проверить права, подключить канал, поставить на паузу |
| `/автопост вкл` | Проверить права и разрешить расписание |
| `/автопост выкл` | Приостановить автоматическую публикацию |
| `/событие текст` | Передать сведения, разрешённые к публикации |
| `/пост` | Просмотреть последний готовый черновик |
| `/пост новый тема` | Подготовить черновик без отправки в канал |
| `/пост авто тема` | Подготовить черновик, самостоятельно выбрав следующего автора |
| `/пост опубликовать ID` | Явно выпустить выбранный пост вручную |
| `/пост убрать ID` | Закрыть черновик или проверенную неопределённую доставку |
| `/комменты вкл` | Разрешить ответы в привязанном обсуждении |
| `/комменты выкл` | Приостановить ответы в обсуждении |

Та же очередь доступна в локальной панели. Ручная публикация возможна
при выключенном расписании; автоматическая всегда учитывает паузу.
Смена канала приостанавливает выпуск. Черновик, созданный для прежнего
канала, автоматически в новый канал не переносится.

CLI из корня проекта:

```powershell
python -m joker channel status
python -m joker channel bind '@имя_канала'
python -m joker channel on
python -m joker channel off
python -m joker channel next
python -m joker channel draft 'Тема черновика'
python -m joker channel draft 'Тема черновика' --auto-role
python -m joker channel comments on
python -m joker channel comments status
python -m joker channel comments off
python -m joker channel show ID
python -m joker channel attach ID --photo 'ПОЛНЫЙ_ПУТЬ_В_ПАПКЕ_ИЛЛЮСТРАЦИЙ'
python -m joker channel publish ID
python -m joker channel publish ID --manual
python -m joker channel discard ID
```

`seed` однократно добавляет стартовые материалы; `import файл.json`
добавляет редакционный материал. Обе команды создают черновики.
Один только `serve --telegram` не запускает генератор изображений и расписание.
Возврат расписания требует отдельного решения владельца и настройки Codex.

## Доставка и защита

Перед отправкой проверяются тип «канал», право бота публиковать и права
владельца. Старую группу бот не использует для публикаций.
Админские команды не принимаются от посторонних. Локальная панель
сохраняет проверку Host, Origin и CSRF. Картинки выдаются только из двух
разрешённых каталогов с проверкой формата, размера и разрешённого пути.
В общий репозиторий не попадают токены и приватная база.

У Bot API нет ключа идемпотентности для отправки. При разрыве соединения
результат может остаться неизвестным. Поэтому очередь помечает его
`uncertain`, блокирует следующие автоматические выпуски и не повторяет
запрос. Даже спустя много новых черновиков такая проблема остаётся видна.
Проверьте канал вручную, затем закройте запись через `/пост убрать ID`.
Эта команда ничего не удаляет в Telegram и не отправляет повторный пост.
Если процесс завершился в момент отправки, остаётся `publishing`:
это также блокирует расписание; сначала остановите отправитель и проверьте
канал, затем восстановите локальный статус с технической помощью.
Для длинных историй фотография и текст — два запроса, поэтому при сбое
между ними возможен одинокий пост с картинкой. Автоматический повтор
целого выпуска запрещён.

Набор проверок: права и тип чата, публичный источник вместо частной памяти,
структурированный JSON от Codex, multipart фотографии, ограничение каталогов,
два конкурирующих отправителя, пауза между фото и текстом, неопределённая
доставка, повтор расписания и отмена генерации. Проверки используют тестовый
Telegram-адаптер; настоящая доставка отдельно проверена первым выпуском.

## Авторы и комментарии

Панель предлагает флажок «Автор меняется сам». Автор выбирается из
сохранённых ролей с учётом последних 30 черновиков и публикаций: сначала
редко использованные, затем те, кто дольше не появлялся. Личная активная
роль владельца при этом не меняется. Профиль автора сохраняется в посте:
поздняя смена роли не превращает ответ сантехника в ответ домохозяйки.
Выбор автора сам по себе не включает расписание и не публикует черновик.

Для комментариев нужно привязать группу через «Управление каналом →
Обсуждение» и добавить туда бота администратором. Приложение проверяет
`linked_chat_id` и права бота раз в минуту. Настройку BotFather Privacy
менять не требуется: администратор получает сообщения группы.
См. [Bot API](https://core.telegram.org/bots/api) и
[FAQ Telegram](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

Ответчик работает, пока запущен `python -m joker serve --telegram` или
`python -m joker telegram`. Он отвечает только в ветках опубликованных
через приложение постов, сопоставляя автоматический пересланный корень
обсуждения и последующие ответы. Для старой вложенной ветки, которую бот
ещё не видел, может понадобиться новый комментарий непосредственно к посту.
Сообщения в группе вне таких веток и сообщения других ботов игнорируются.

Контекст ответа: сохранённая роль автора, публичный пост и четыре последних
публичных обмена в той же ветке. Личная память и диалог владельца туда не
подставляются. Команды из комментариев не вызывают функции владельца.
Ответ обычно занимает 1–3 предложения; модель может пропустить спам.
Ограничения: три входящих комментария от человека в минуту, 20 ожидающих
и 50 принятых за сутки UTC; вызовы модели также расходуют общий дневной
лимит. Входящие личные запросы имеют приоритет перед очередью комментариев.

В панели есть отдельные кнопки включения и паузы ответов. Неопределённая
доставка не повторяется автоматически: её ID появляется в состоянии
комментариев для ручной проверки. При перезапуске незавершённый расчёт
можно повторить, а отправка, исход которой неизвестен, остаётся на проверке.
