# Minecraft через UnionClef

Обновлено 21 октября 2026. Это следующий этап после работающих текста,
памяти, масок, Telegram и панели. Публичный репозиторий уже существует:
[Kuzemko03/AiTalentHub-Persona](https://github.com/Kuzemko03/AiTalentHub-Persona).

## Что добавлено

- Адаптер к локальному Py4J UnionClef и приём разобранного игрового чата.
- Ответ только при обращении по имени Джокера, его игровому нику или имени маски.
- По решению модели: следование за настроенным владельцем; подход
  с остановкой в пределах трёх блоков. «Добудь 16 дубовых брёвен» — в инвентарь
  Джокера, «принеси 16 дубовых брёвен» — также подойти и выбросить их владельцу.
  Поддерживаются дуб, булыжник и земля, от 1 до 256 предметов.
  Формулировку и количество понимает модель; при недостатке данных она может уточнить.
- Точное «стоп», `/stop`, `/стоп` и кнопка остановки имеют приоритет
  над очередью ответов. Проверяется, исчезла ли активная задача UnionClef.
- Смена маски и создание нового образа отменяют старый текстовый ответ,
  но сохраняют игровое поручение. Само переключение не отправляет stop в игру.
- В панели — состояние игры и кнопки следования, добычи и остановки.

Модель выбирает типизированный инструмент, затем приложение проверяет права
и аргументы и вызывает мост. Фразы пользователя не разбираются игровым исполнителем.
Каталог ресурсов — данные в `agent/shared/minecraft-items.json`.
[Описание цикла и событий](workplace.md). Пустая очередь задач не означает,
что ресурс добыт. Нужное количество проверяется через `getInventoryFull()`;
это состояние `collected`. Для передачи сначала останавливается добыча,
потом Джокер подходит к владельцу, останавливается и проверяет расстояние
и отсутствие открытого меню. Полный стак выбрасывается только если его размер
не превышает остаток поручения; иначе выбрасывается по одному предмету.
После каждой операции проверяется точное уменьшение инвентаря. При неизвестном
результате повтор не выполняется. Ограничение поручения — 15 минут.

`delivered_unverified` подтверждает только выбрасывание нужного количества
рядом с владельцем: подбор игроком ещё требует ручной проверки.
`idle_unverified` и `unconfirmed` не означают успех. Задачи не восстанавливаются
автоматически после обрыва связи; сохранённое намерение автономного цикла
требует проверки владельцем. [Подробнее о цикле](operations.md).

## Подготовка

Профиль курса: Minecraft Java 1.21.11, Fabric, Java 21 и основной JAR
[UnionClef](https://github.com/3ndetz/unionclef/releases/latest).
Порядок установки — в [инструкции курса](https://course.personalabs.ru/instructions/minecraft).
Вторые копии включённых в UnionClef модулей рядом с основным JAR не нужны.
Игра запускается отдельным клиентом под собственным ником Джокера.

В папке проекта установите опциональную зависимость в существующее окружение:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[minecraft]"
```

В локальный `.env` добавьте реальные игровые ники. Ниже — только образец:

```dotenv
MINECRAFT_ENABLED=0
MINECRAFT_OWNER=YourPlayer
MINECRAFT_BOT=JokerBot
MINECRAFT_PORT=25333
MINECRAFT_CALLBACK_PORT=25334
```

`MINECRAFT_ENABLED=0` сохраняет обычный запуск без игры. Разовый флаг
`--minecraft` включает адаптер явно. Значение 1 подключает его при запуске
приложения без дополнительного флага. Ники владельца и Джокера различаются.
Проверяется реальное имя игрового клиента. Ник активной маски не меняет
учётную запись Minecraft.

Оба Py4J-порта используются только на 127.0.0.1. Не запускайте одновременно
два Python-адаптера на одном callback-порту. При смене Python-порта адаптер
настраивает обратный вызов в Java через resetCallbackClient.

## Запуск

Сначала откройте мир в игровом профиле с UnionClef, затем:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m joker doctor
.\.venv\Scripts\python.exe -X utf8 -m joker serve --minecraft
```

Панель — http://127.0.0.1:8765. В диагностике отдельно видны доступность порта
и наличие настройки ников. Доступный TCP-порт сам по себе ещё не подтверждает
корректный игровой API: адаптер дополнительно проверяет мир, ник и callbacks.

Для единого процесса с уже настроенным Telegram:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m joker serve --minecraft --telegram
# или
.\Start-Joker.ps1 -Minecraft
```

Перед этим завершите старый экземпляр панели/Telegram. Повторный long polling
одного бота двумя процессами будет конфликтовать. Для одной игры без панели
есть режим `python -m joker minecraft`.

## Игровой чат и права

Владелец пишет обычные фразы: «Джокер, будь ИИ-инженером», «Джокер, за мной»,
«Джокер, принеси 16 дубовых брёвен», «Джокер, стоп». Для срочной остановки
от настроенного владельца обращение по имени не обязательно.

Ники берутся из поля `user` разобранного сообщения UnionClef; строки без
определённого автора и `parse_type=unparsed` не управляют приложением.
Собственные сообщения, необращённые реплики и переполненная очередь отбрасываются.
Очередь ограничена 16 событиями; обычные ответы отправляются не чаще раза в 3 секунды.
Ожидание события и проверка состояния игры не вызывают модель и не тратят её лимит.

Гость может обратиться к персонажу и получить текстовый ответ, но не менять
общую маску, останавливать Джокера или задавать игровые действия. Память
изолирована по игровому нику и отделена от личного Telegram-чата владельца.
Команды редакции канала и личной памяти из Minecraft не принимаются даже
от игрового владельца. Ответ модели не может превратиться в серверную команду:
префиксы `/`, `@`, `;`, `!`, `$` в начале ответа убираются.

Разрешение по игровому нику рассчитано на собственный или доверенный сервер.
Это не самостоятельная криптографическая проверка личности: на сервере,
который подделывает автора, доверять нику нельзя.

## Остановка и переподключение

Ответ «поручение передано» означает приём команды адаптером, а не результат
действия. Остановка вызывает `stopPathing()` и проверяет `hasActiveTask()`;
если подтверждения нет, интерфейс сообщает об этом. После потери соединения
не гарантируется, что игровой клиент физически остановился.

При обрыве связи очередь старого подключения очищается, старый ответ модели
не отправляется в новый мир. Поручения не воспроизводятся после переподключения
или перезапуска. Если в игре уже осталась активная задача, сначала требуется
явное «стоп». При нормальном завершении приложения отправляется остановка;
при аварийном завершении процесса/ПК такой гарантии нет.

## Проверка в настоящем мире

1. `doctor` видит порт и настроенные ники; панель показывает подключение.
2. Владелец пишет «Джокер, привет»; приходит один ответ текущей маски без эха.
3. «За мной» действительно начинает следование, «стоп» прекращает его.
4. Во время следования меняется маска; задача продолжает работать.
5. В тестовом мире запросить 16 дубовых брёвен и проверить инвентарь вручную.
6. Пока модель отвечает, нажать «стоп»: старый текст больше не приходит.
7. Выйти из мира и вернуться: старые задачи/реплики не воспроизводятся.
8. Проверить, что обычный игрок не может переключить маску и командовать ботом.

Эта живая проверка пока не выполнена: 21 октября 2026 локальный порт 25333
был недоступен, игровые ники не были настроены. Выполнены автоматические
проверки адаптера и фактических параметров установленной библиотеки Py4J;
они не заменяют запуск игры. Голос и автономный цикл уже реализованы для
последующей проверки — см. [план](roadmap.md).
